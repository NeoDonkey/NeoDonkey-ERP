# Tests that are known to fail intermittently for a reason that is NOT the change under test.
#
# A line here means: if this test is the ONLY thing failing, CI warns and passes. If anything
# else fails, the build fails as normal. One substring per line; blank lines and # are ignored.
#
# This is a compromise, and it is recorded as one in docs/COMPROMISES.md with an exit path.
# The alternative was worse: `test` is a required check, so a test that fails one run in eight
# blocks every pull request in the queue for a reason no agent can reproduce, and nothing here
# presses re-run. A known-flaky test inside a blocking check does not raise the quality bar, it
# lowers throughput to zero at random.
#
# The rules that keep this from becoming a dumping ground, enforced by
# test/known-flaky.test.js:
#
#   1. Every entry names an open issue. No issue, no quarantine.
#   2. At most three entries. If you need a fourth, the suite has a problem worth stopping for.
#   3. Adding one is a compromise: it belongs in docs/COMPROMISES.md, and the reviewer refuses
#      a pull request that adds a line here without an entry there.
#
# Removing a line is always allowed and never needs justification.
